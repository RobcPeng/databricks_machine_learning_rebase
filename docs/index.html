Why each bundle matters

The payoff, stated plainly

obj_recg · computer vision

Choose a vision model on evidence

Model choice in computer vision costs real money: GPU time, a latency budget, a deployment surface. This bundle turns that choice into a measurement. The same footage runs through nine model specs on one axis, with latency, size, and accuracy side by side, so a team commits to YOLO, an R-CNN, or a transformer because the leaderboard said so.

A second layer connects sight to decisions. Biomechanics and game results feed win-probability, athlete-index, and scholarship-ROI models, which shows learners how a computer-vision pipeline reaches an operational question.

pca_ica · dimensionality reduction

Test whether a method helps before you trust it

Analysts get handed wide, messy survey and administrative data and asked which factors drive an outcome. This bundle answers the prior question first: does compressing the feature space with PCA, ICA, or random projection actually improve the prediction, and which factors carry the signal?

It runs on public, governed, reproducible data and also runs off-platform for fast local iteration, so anyone can read it line by line and adapt the pattern to their own records.

The shared value

A benchmark harness is cheap insurance. It replaces "we think this model is best" with a leaderboard, keeps the choice reproducible and governed under Unity Catalog, and stays useful as the field grows, since adding a model, dataset, or reducer is a one-line registry append.

The shape

Same three moves, both times

The two bundles share no code. Each has its own databricks.yml, package, and job. What they share is a rhythm.

01

Deploy the bundle

One command stands up the schema, volume, pipeline, and job under the rpeng_upleveling catalog.

02

Run one job

A single job fans out across the model grid on serverless compute (GPU for vision, CPU for the classic sweep) and logs each run to MLflow.

03

Read the gold leaderboard

The last task writes a comparison table to the gold schema. One row per model, the metrics side by side.

Shared conventions

What holds both bundles together

Asset Bundles
Each bundle declares its schemas, volume, pipeline, and job under resources/ and deploys with the Databricks CLI. No shared code, so you run them independently.
Medallion + MLflow
A bronze, silver, gold flow feeds training; every run logs to MLflow; the final task writes a gold comparison table.
Catalog
One catalog, rpeng_upleveling, with one schema family per bundle.
Registry-driven
Add a model, dataset, or reducer by appending one entry to a registry. Dispatch, evaluation, and the leaderboard pick it up.
Honest status

These are benchmark harnesses. The grids, pipelines, and leaderboard plumbing are wired end to end, but several trainers, evaluators, and gold features are still stubbed, and no results are published here. The roadmap lists what is implemented versus what remains. No invented numbers stand in for a run that has not happened.
