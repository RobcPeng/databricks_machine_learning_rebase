From a wide table to the few factors that matter.

This bundle asks whether we can predict an above-median earnings or attainment outcome for a graduate, an institution, or a student, and whether PCA, ICA, random projection, or clustering-derived features help the classic models get there. Scikit-learn on serverless CPU, with the option to iterate off-platform against public URLs for fast local feedback.

Step 0

What it is: binary classification

Every target in this bundle is a median split of a continuous outcome. Label 1 means above the median; label 0 means at or below it. Because the split is at the median, classes are exactly balanced at 50/50.

A balanced split means accuracy, F1, and ROC-AUC are all honest: no class is over-represented and no metric is artificially inflated by an imbalanced prior. ROC-AUC is the primary ranking metric, because it measures discrimination across all classification thresholds without assuming a fixed operating point. The leaderboard sorts by test ROC-AUC descending.

Why median?

Continuous targets like average earnings or occupational status scores vary enormously across datasets and populations. Splitting at the median gives a common question across all four sources: is this graduate, institution, county, or student above the middle of its own reference distribution? The trade is losing the magnitude of the difference; the gain is comparability across sources with different scales and units.

Step 2

Deploy the bundle and run the job

From the pca_ica/ directory, two commands stand up the bundle and start the benchmark:

# from the pca_ica/ directory · target sled
databricks bundle deploy -t sled -p SLED_fe_demo
databricks bundle run dr_benchmark -t sled -p SLED_fe_demo

The deploy step creates the schemas, volume, and job under the sled target. The run step fans the 192-cell grid out across serverless CPU workers and logs every run to MLflow as nested child runs.

Off-platform iteration

The same code runs locally. Install the requirements, then run pytest tests/ from pca_ica/. Off Databricks, the data loader fetches each dataset from its public URL instead of reading the silver schema. This is the fastest way to iterate on a reducer, classifier, or dataset configuration before deploying.

pip install -r requirements.txt
pytest tests/

Step 4

The pipeline per grid cell

Each of the 192 cells runs the same four-stage pipeline. The reducer is typically the only variable that changes between two adjacent cells, which isolates its effect cleanly.

01

Preprocess

Impute missing values and standard-scale all numeric columns. One-hot encode categoricals, capped at 50 unique categories per column to bound feature width. Output is a dense numeric matrix ready for any reducer or classifier downstream.

02

Reduce (optional)

Apply the configured reducer: none, pca, ica, or random_projection. When set to none, the full preprocessed matrix passes through unchanged and serves as the baseline every other reducer must beat.

03

Cluster features (optional)

Fit a clustering model on the (optionally reduced) training features and append one-hot membership columns to every row. This step is off by default. When it runs, the cluster assignments join the feature matrix before the classifier sees it.

04

Model

Fit the configured classifier on the training fold and evaluate on the held-out test fold. Log accuracy, F1, and ROC-AUC (both cross-validation and test) to an MLflow child run under the parent dataset run.

Step 5

The four reducers

One of these four keys fills the reducer slot in each grid cell. The none baseline must always run first: every other reducer is evaluated by whether it improves on that score.

key: none · control

Full space (control)

The full preprocessed feature matrix goes straight to the classifier with no rotation, compression, or projection. Every other reducer is judged by whether it improves test ROC-AUC over this score.

key: pca · scikit-learn PCA

PCA

Rotates the data to the directions of greatest variance and keeps the top k components (default 10). Components are uncorrelated linear blends of all original features. The fraction of variance the top k components retain is logged as pca_explained_var.

Trade: linear only, so non-linear structure is invisible to it. Each component mixes contributions from many features; reading the loadings is the primary interpretation tool.

key: ica · FastICA, whiten unit-variance

ICA

Finds statistically independent axes by maximizing non-Gaussianity. Configuration: FastICA with unit-variance whitening, max_iter=1000, tol=1e-3. Where PCA finds uncorrelated components ordered by variance, ICA finds components that are as statistically independent as possible, separating mixed signals into their sources.

Trade: components are unordered, convergence is not guaranteed on every dataset, and fitting is more expensive than PCA.

key: random_projection · Gaussian RP

Random projection

Multiplies the feature matrix by a random Gaussian matrix. The Johnson-Lindenstrauss lemma guarantees that pairwise distances are approximately preserved. Nearly free to compute.

Trade: no semantic structure, adds noise, and the projected space is not interpretable. Its value in this grid is as a fast lower-bound comparison: if random projection beats the full space, something about the original dimensionality was hurting the classifier.

Step 6

Clustering as features

After the optional reduce step, the pipeline can append cluster-membership columns to the feature matrix. This answers a structural question the classifier cannot ask on its own: which cohort does this record belong to? That signal can lift classifiers that struggle with non-convex decision regions.

key: kmeans · default on

K-Means

Fits K-Means with 4 clusters on the (optionally reduced) training features, then appends one-hot membership columns to every row in both training and test splits. The four binary columns give the classifier explicit cohort signals. Included in the default sweep.

key: gmm · registered, off by default

Gaussian mixture

A Gaussian mixture model over the same feature space. Soft membership probabilities replace K-Means hard assignments: each row gets a probability for each mixture component rather than a binary flag. Registered in the grid but excluded from the default sweep to keep cell count manageable.

Step 7

The classifiers

Seven classifiers are registered; six run in the default sweep. svm_linear is off by default. Each cell in the grid uses exactly one.

Classifiers registered in the dr_bench bundle
Key What it is Strengths Watch-outs Reach for it when
logistic_regression Linear model of log-odds Fast, interpretable coefficients, calibrated probabilities No native non-linearities; requires scaling The baseline. Run it first on every dataset.
svm_rbf SVM with RBF kernel Flexible non-linear decision boundaries Quadratic training cost; the sweep caps rows at roughly 6,000 for this reason Small-to-medium data. Often the best single model after a well-chosen reduction.
svm_linear Linear-kernel SVM Handles wide, sparse one-hot spaces well Slower than logistic regression with limited additional benefit in most settings; off by default Features already occupy a good linear space and you want a margin-based classifier.
knn k-nearest neighbors (k = 7) Non-parametric, captures irregular local structure Slow at inference; sensitive to scale and noise Irregular decision boundaries. Gains most from PCA or ICA denoising.
random_forest 300 bagged decision trees Handles mixed feature types; built-in feature importance Memory-heavy; reduction can sometimes discard signal it relies on A strong tabular baseline when you also want variable importances.
xgboost Gradient-boosted trees (depth 4, 300 rounds) State-of-the-art on tabular data; handles missing values natively More hyperparameters; sequential training The model to beat. If XGBoost on the full space loses to a reduced space, the reducer is doing something real.
mlp Small neural net: 64 then 32 units Captures non-linear interactions Requires scaling; slow on CPU Sanity check against the tree models. Rarely wins on small tabular data.
Step 8

Run the grid and read the leaderboard

The default grid spans 4 datasets, 4 reducer configurations (none, plus PCA, ICA, and random projection each at a default component count), 2 clustering states (K-Means on or off), and 6 classifiers: 4 × 4 × 2 × 6 = 192 cells. Every cell is a nested MLflow child run under its parent dataset run.

Leaderboard columns

The gold leaderboard table at rpeng_upleveling.dimensionality_reduction_03_gold.dr_leaderboard holds one row per grid cell. No results are published here; the schema describes what the table will contain once the full run completes.

The model_comparison view aggregates the best test_roc_auc per (dataset, model, reducer) triple for quick cross-model reading without scanning individual cells.

Three questions to ask of the leaderboard

01

Does reduction beat none?

Compare the best cell per reducer against the best none cell on the same dataset and model. If PCA or ICA improves test ROC-AUC over the full space, the reduction is doing real work: denoising, collapsing collinear dimensions, or both. If random projection also beats none, the original feature count was simply too large for the classifier regardless of structure.

02

Do K-Means cluster features add lift?

Compare the clustering-on and clustering-off cells for the same (dataset, reducer, model) triple. A consistent lift means cohort membership is a genuine signal. No lift means the classifier already captures the grouping structure through the features themselves.

03

How does pca_explained_var track ROC-AUC?

Sort by pca_explained_var for a fixed (dataset, model) pair and watch how ROC-AUC moves. If ROC-AUC peaks well below 1.0 explained variance, the predictive signal concentrates in a low-rank subspace and the remaining variance is noise. If ROC-AUC keeps climbing as you add components, the signal is distributed and aggressive reduction hurts.

Each registered model carries the full sklearn pipeline: preprocessor, reducer (if any), cluster featurizer (if any), and classifier. Logged artifact lineage in MLflow links the registered model back to the run that produced it.

Reading outcomes

Reading outcomes from the factors

The four datasets mix attributes a program cannot change and actions it can take. Understanding which kind of attribute loads onto which factor is what makes results interpretable and actionable.

Attributes a program cannot change

Background and demographic features

Age, birthplace, race and ethnicity, parental education, prior academic preparation, disability status, English proficiency. These attributes describe who a student or graduate is. A model trained on them can predict outcomes, but a program cannot act on them to change anyone's trajectory.

Keep these features in the analysis for fairness auditing: you need them to measure whether a model produces disparate outcomes. Remove them from any scoring pipeline that touches individual decisions.

Actions a program can take

Policy and program features

Admissions selectivity, tuition and net price, financial aid generosity, advising intensity, program design, field of study, school climate, hours worked, credential level. A factor that co-moves with earnings and loads heavily on these attributes names a place to investigate for intervention.

How to read a PCA component

A PCA component is a weighted recipe over the original features. Sort the loadings by absolute value and read the five to ten heaviest. The pattern names the latent factor. Two examples from the institution-level data:

  • Low admit rate + high SAT average + high total cost + high completion rate: a "selectivity and resources" factor. Institutions that score high here tend to post high median earnings, but the factor conflates exclusion with investment. High loadings here do not imply a transferable program design.
  • High Pell share + open admissions + regional locale + low cost: an "access mission" factor. Institutions here serve lower-income students; strong earnings on this factor signal real value-add against a harder starting population.

The same reading applies to NSCG or ACS: components that blend field of study, hours worked, and credential level onto one axis describe an intensity-of-investment factor distinct from an employer-market factor that loads on sector, location, and industry.

How to read an ICA component

ICA components are statistically independent sources. Where PCA might place student background and program intensity on the same axis because they correlate in the raw data, ICA separates them: a "student background" source and a "program intensity" source can each vary without the other moving. If one source predicts outcomes after you hold the other fixed, it is doing independent explanatory work.

Fairness, privacy, and legal obligations

Reduction surfaces associations, not causes. A factor that co-moves with an outcome is a place to investigate, not a verdict on a person. Keep demographic attributes in the pipeline for fairness auditing; run the full analysis under Unity Catalog access controls and data lineage so every model and query can be reviewed. Respect FERPA and equivalent state law: student-level records are protected. Pair any predictions that could affect an individual with human review before that prediction reaches a decision about a student.
